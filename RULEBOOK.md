# nMEMORY (Python Port) — RULEBOOK & CANONICAL MAPPINGS

## §0 — Prime Directive & Posture
- **BAR:** Tier S+. Zero workarounds and zero unnecessary exposed complexity — bounded resources, fail-closed trust boundaries, tested declared failures, deterministic recovery, post-recovery readback. S+ never means maximal machinery: smallest sufficient design; speculative abstraction is a defect.
- **POSTURE:** Preserve core semantics (behavior, data shapes, tool contracts) unless changing them is the deliberate subject of the work. A defect is fixed with its regression test; slowness is measured before it is changed.
- **PROCESS EVOLUTION:** A failure occurring twice indicts a rule — amend `RULEBOOK.md` in the same commit as the fix; never patch the same class of bug twice without a rule change.
- **OWNER RULE PROJECTION:** `capsule list --pinned --full` shows each owner rule (an untainted user-stated pin) with visible text, or counts it under the owner-rules heading. A shown rule is never empty or a bare "…" unless that is its text. A headline that leaves out any text ends in "…". A pin that the CLI cannot read is counted there as possibly an owner rule. One function, `_owner_headline`, makes the decision. The property test `test_every_owner_rule_shows_with_visible_text_or_is_counted` holds the invariant. A new case of this class extends that test first.
- **RULE FILES:** Owner rules reach sessions through `~/.nott/RULES.md` (the user-scope rules of every project) and `<root>/.nott/RULES.md` (one project's project-scope rules), which `nmemory rule write` (`nmemory/rules.py`) generates from the live pins. Only the SessionStart hook runs it, and it writes a project file only for a tree whose CLAUDE.md imports it, never for `$HOME`. The files are output only: a rule that names its project is project scope, every other scope is a System1 `scope` observation in `jev_observations`, and an unanswered or `nenhuma` rule is project scope, named in the header and asked again. One line per rule, `cap-<id>: <first paragraph>`, the text unchanged, cut at 200 characters, and ending in "…" whenever it leaves out any text. A file that differs only in `generated:` is not rewritten, and the scope answers are stored after the files are written (best effort). Tainted and unreadable pins are only counted. Each rule left out is named: `merged: a->b` (word 3-gram Jaccard at `NEAR_DUPLICATE`) and `in_plugin: id (file)` (at least `IN_PLUGIN` of its 5-grams in one plugin file). An ingest of a user-stated decision, procedure or constraint with a verified source quote is pinned in the same transaction.
- **DISPLAY CENSUS:** The CLI digest explicitly opens a read-only (`mode=ro`) store connection without migration or snapshot loading. Its subtree fence and counts come from stored rows; headline limits never truncate the census. This display cannot establish canonical integrity or authorize a writer.
- **RECALL ACCOUNTING:** Ordinary recall excludes dod with a named count; an explicit effort/topic set bypasses that kind fence. Every scope exclusion of a retrieved candidate is counted. Classification lookup is limited to those candidates; direct id and work-graph consumers remain available.
- **EMBEDDING LIFECYCLE PROOF:** Completion proves current-text vector coverage of the live corpus in the same writer boundary as activation. An empty queue or a fixture seeded as ready supplies no such proof. Readiness regressions schedule a collector between the worker's transition and queue writes and read recall and context back. Completion regressions also collect delayed results after rollback and text requeue; an answer without its submitted capsule, text and space identity cannot witness completion.

## §1 — Ecosystem & Constraints
1. **Sync Functional Core, Threads at Doors:** The core domain logic, stores, retrieval, and analysis are synchronous and deterministic and do not use asyncio: concurrency is handled by threads at network/socket doors.
2. **Dependencies:** Standard library first. The store is one SQLite file opened only through `nott_database.connect`. `sqlite-vec` provides `vec_distance_cosine` for the embeddings. No PostgreSQL use enters (Rail P).
3. **No Sentinel Values:** Rust `Option<T>` maps strictly to `Optional[T]` / `T | None`. Never use sentinel values (e.g. `""`, `-1`, `"none"`).
4. **Typed Exception Hierarchy:** All exceptions root in a single base class `NMemoryError`. No bare `except:`, no `except Exception: pass` on persistence, trust, or protocol paths.
5. **Validating Constructors:** Illegal states are unrepresentable. Constructors reject invalid inputs immediately (fail-closed), never coerce or silently mutate invalid data.
6. **Rails & Tooling:** Python is pinned in `.python-version` and tool floors live in `rails/floors.toml`; mypy runs in strict mode. The MCP protocol (framing, handshake, version negotiation) is the official MCP Python SDK's (`mcp`); nMEMORY owns only its tool catalogue and call boundary.

## §2 — Canonical Rust-to-Python Mappings
| Rust Construct | Canonical Python Construct | Notes |
| :--- | :--- | :--- |
| `Result<T, E>` | Return `T` or raise subclass of `NMemoryError` | Rooted in `NMemoryError`, typed subclasses per domain |
| `Option<T>` | `Optional[T]` (`T | None`) | Never sentinel values |
| `enum` (data-less) | `enum.StrEnum` / `enum.Enum` | String serialization matches Rust serde exact casing |
| `enum` (with data) | Discriminated union / Tagged dataclasses | Explicit tag field e.g. `outcome: Literal[...]` |
| `struct` (plain data) | `@dataclass(slots=True)` | Immutable where appropriate (`frozen=True`) |
| `struct` with invariants | Class with `__post_init__` validation | Raises `CapsuleError` / `StoreError` on invalid invariants |
| `rusqlite::Connection` | `sqlite3.Connection` | `isolation_level=None` (autocommit) or explicit transactions |
| `tokio::select!` / `mpsc` | `threading.Thread`, `queue.Queue` | Allowed ONLY at the stdio door's background workers (embedding worker); core remains pure sync |
| `serde::Serialize` | `dataclasses.asdict()` or custom JSON serializers | Keys match Rust serde output byte-for-byte |
| `serde::Deserialize` | Validating classmethods / parser functions | Distinguishes deserialization faults from execution faults |
| `sha256` / `hmac` | `hashlib.sha256()`, `hmac.new()` | Produces identical lowercase hex strings |

## §3 — Semantic Traps & Parity Verification
Refer to PORTING.md at commit 497f4ec26 (retired with the Rust donor in PR 157) for the canonical catalog of the 8 semantic traps discovered during porting:
1. **Integer Div/Mod Sign:** Rust `/` and `%` truncate toward zero; Python `//` and `%` floor toward negative infinity. Mitigate via `int(a / b)` and `math.fmod`.
2. **f64 JSON Formatting:** Rust `1.0` vs Python `1.0` vs integer `1`, and `-0.0` vs `0.0`. Mitigate via custom serializers and float normalization.
3. **u64 Wrapping Arithmetic:** Python integers have arbitrary precision; Rust types wrap or panic. Mitigate via explicit `& 0xFFFFFFFFFFFFFFFF`.
4. **Dictionary Ordering in Serialization:** Rust `BTreeMap` is key-sorted; Python `dict` is insertion-ordered. Mitigate via explicit key sorting before JSON serialization.
5. **Char vs Byte Indexing:** Multi-byte UTF-8 character indexing differences (`len()`, slices, slugify). Mitigate via char iteration and Unicode diacritic folding tables.
6. **Panic vs Exception Taxonomy:** Fail-closed graceful error handling. Invalid input returns structured JSON-RPC errors, never unhandled server panics.
7. **Drop vs GC Finalization:** Python GC delay on file and database connection cleanup. Mitigate via explicit context managers (`with`) and connection pool limits.
8. **Checked & Saturating Arithmetic:** Confidence bounds, score weights, decay calculations. Clamp float values strictly within `[0.0, 1.0]`.

All ported code must strictly respect the mitigations and invariants specified in the `PORTING.md` traps table.

## §4 — Derived output integrity
- Capture results distinguish an existing row from a concurrent insertion winner. A concurrent loser preserves the winner's classification, evidence, provenance, and taint. Regression tests use different explicit kinds and source quotes, in both taint directions. Sequential recapture keeps its explicit reclassification contract.
- Engine-owned output fields must come from their producing observation, including partial-scan counters and failure status. Missing provenance or capture metadata remains explicit absence; never substitute the reader environment or a plausible constant. Regression proof changes the underlying state and checks both resulting values.
- A failure a paid pass cannot get past stops the pass. When the provider refuses the account itself (HTTP 401, 402 or 403, a 429 whose `result` carries an account code such as Z.ai's `[1113]` or `[1308]` to `[1321]`, or a null status whose `result` says `Not logged in`), the daily curator stops at the first capsule and ends with `daily review failed` naming that refusal. Each candidate it did not reach is marked `curator_daily_failed` with the reason `not reached: <provider error>`, so the audit trail tells it from a capsule that was tried and it stays in the queue; a transient error (a rate limit or overload without an account code, a 5xx) still fails only its own capsule. A child CLI's own retry loop is capped below the caller's timeout, and its error is read where the CLI writes it (the stdout result object).
- `nmemory_capsule_list` forward paging is opt-in through `page_size`; `with_record:true` is accepted only with paging and adds the full `nmemory_capsule_show` result under each row's `record` field within `LIST_RECORD_PAGE_MAX_BYTES`, the complete 4 MiB JSON-RPC stdio response-frame bound. A page may end short (or empty) with `next_cursor` at its last included row, so the walk continues without truncating, skipping or repeating records; a record that cannot fit alone is refused by capsule id and budget. The cursor binds this flag, and requests that omit it keep their existing compact response.
- A whole-range `nmemory_capsule_list` selects `kind` in SQL (`ListFilter.kind`), so the rows it decodes are the rows of that kind; filtering after the fetch decoded a whole project to return one session index row. A forward page keeps `kind` as a sidecar filter applied after the cut, which its continuation is bound to, and `list_page` refuses a kind.
- A per-capsule derivation on a render path (`nmemory_capsule_show`, each `with_record` row) reads the rows around that capsule through an indexed lookup (`list_relations_for`), never the whole relation table: `dod_contradictions` decoded every live relation per rendered capsule, 110,630 rows for one 14-record conversation replay.
- A capture or read is filed under the session its client names, in the environment it gives the server (`CLAUDE_CODE_SESSION_ID`) or in the call's own `_meta.sessionId` (Codex), and a claim that a client names none carries the client version it was measured on: Codex sent no `_meta` when `client_key` was written, 0.160.1 names its session on every `tools/call`, and 6,725 Codex captures were filed under `unknown` in between.
- A set that a per-call path derives from an append-mostly table is kept by triggers in the transaction that writes the table, never rebuilt on the call: the inbox's `served` CTE unpacked all 1.80 M `read_traffic` rows (31.8 M ids, 7.7 s) on every `nmemory_context_show`, and the `served` table now answers it by key. Such a step is additive: a writable open adds it, `user_version` stays 1, and a read-only open never writes it.
- The last-read aggregate covers only non-revoked traffic with a TEXT JSON array of strings that can be read as UTF-8 and a TEXT time that `ts()` parses into a representable UTC datetime. SQLite checks the JSON types and reads the IDs. Times stay integer microseconds until the final result. A row outside this domain invalidates the aggregate with a stored reason. Invalid or incomplete coverage uses the unchanged full scan, including its candidate-specific refusals. Only a full check on a writable open can restore validity.
- An archive consolidation made for a `supersedes` edge ends with the edge: once no live edge supersedes the capsule, the same pass returns it to active, reading back the reason it journaled for the capsule's latest tier event. Revocation reached every reader of the edge but not the archive the edge caused: four owner rules archived one second after their `supersedes` edges (2026-10-07) had no way back to default recall. The reason binds only where nothing else shares that event's instant, one tier event and one consolidation event, and never to an event the U5 migration reconstructed (before tier events, a second archive at the same instant overwrote the row without a trace); any other archive stays. Every tier move is planned again under the write lock, and one the store no longer plans (an edge, a tier, a purge or a recall landed after the plan's read) is dropped with nothing journaled.
- Two writers keep the term index: `CapsuleRepository.insert` and `forget_capsule`. They change it in the transaction that writes the capsule, and only when the stored tokenizer identity is theirs. SQL cannot run the Python tokenizer, so the triggers on `capsules` only mark the index invalid. They fire when another statement changes, deletes or moves an indexed capsule, or inserts a capsule at or below the covered sequence. Recall reads the index only when it is valid, covers the newest capsule and has the current `TOKENIZER`. That identity names the tokenizer version and the Unicode data version. A build creates the index objects before it reads any token, and each build transaction checks the state before it writes.
