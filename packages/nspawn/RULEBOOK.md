# nSPAWN rulebook: the layer interfaces

[Architecture](../../docs/components/nspawn/ARCHITECTURE.md) shows service and trust boundaries.
The [reference](../../docs/components/nspawn/REFERENCE.md) lists source declarations.

The interface contract of nSPAWN's layers, L1–L8 plus L1q (the quota reading that
hangs off L1). Every layer below is built; a row states
what the layer owns, consumes, produces and refuses, and a change to one of those is a
change to this contract. The live door lists exactly the contracts in
`NSPAWN_TOOL_CONTRACTS`, each with a real non-empty `inputSchema`; no count is written
out here.

## Shared contract

- A provider's `kind` selects its executor: `claude` uses Claude Code, `codex` uses
  Codex app-server (FUGU Responses profiles included), `agy` uses AGY stream-json.
  `rows.Backend` is the closed vocabulary the registry admits.
- `requested_provider` records caller intent. `executed_provider` records the route
  actually used. `executed_account` records only a roster alias, never credential
  material. All three may be `None` when no observation exists.
- The core is synchronous. Threads are admitted only at the child I/O boundary;
  `asyncio` is not admitted.
- Every subprocess receives an argv sequence without shell interpretation. Every
  process action is authorized by `ProcessIdentity`, never by a bare PID.
- Credential values must not enter rows, MCP results, transcripts, run metadata, or
  this configuration surface. Child output is redacted before persistence.
- A missing dependency, invalid input, exhausted capacity, output limit, unknown
  process identity, or unclassifiable terminal stream is a typed refusal. There is
  no internal failure sentinel.
- L6 and L7 refuse `native_write` with `read_paths` before a run, claim or child exists.
  The typed refusal tells callers to drop `read_paths` or use `read_only=true` without `native_write`.
  Resumes and continuations obey the same rule. L3 retains its read-only check.
- L6 calls L7; L7 composes L1, L2, L3, L4, L5, and L8. This is dependency direction:
  a lower layer never imports a higher one.

## L1 — the registry

| Contract field | Locked value |
| --- | --- |
| Owns | `nspawn/schema.py` (`SCHEMA_DDL`), the row fields in `nspawn/rows.py`, and the wall methods in `nspawn/registry.py` |
| Consumes | One SQLite file opened only through `nott_database.connect`; `RunRow`; `ProviderWallRecord` and `AccountWallRecord` observations from L5 |
| Produces | `REGISTRY_SCHEMA_VERSION`, carried by `PRAGMA user_version`; live-wall reads and idempotent wall writes |
| Generations | The current generation is 7. The additive `review_heads` table counts distinct heads per subject. The additive `worktree_claim_generations` table keeps one generation for each worktree. Triggers on each claim INSERT, UPDATE and DELETE add one to it. Thus an old claim writer also advances it. An UPDATE that moves the worktree key advances both keys. A row stays when its claim goes, and nothing resets or prunes it. The triggers refuse a change at the largest integer and never wrap it. `Registry.upgrade` installs the table and its triggers in one write. A current store opens with no write. `Registry.open` applies the additive steps in `nspawn/schema.py` once under the write lock. Version 6 adds reversible node holds, workflow bindings, key reservations and first-terminal receipts; unknown generations are refused (`UnrecognizedSchema`). The host-only `nspawn database rollback` can restore generation 5 only after every reserved run is terminal, preserving the additive rows and triggers for idempotent re-upgrade. The door never creates the file: `nspawn database create` does |
| Read startup | `Registry.upgrade` checks the version and additive schema through reads. A current schema takes no write transaction. Missing extensions retain the migration path. MCP reads register no instance and start no heartbeat or slice reconciliation. A read checks for proven owner loss without a write lock. Only a detected loss enters `mark_orphans`, which checks custody again and arms terminal notices. Mutations keep the normal lifecycle. |
| Run columns | Nullable `requested_provider`, `executed_provider`, `executed_account` and `owner` (`node:<session>`, immutable once admitted); `system_prompt` retained |
| Wall tables | Inline DDL only: `provider_walls(provider PK, cooling_until, source, observed_at)` and `account_walls(account_alias PK, cooling_until, source, limit_type, observed_at)` |
| Source vocabulary | `vendor_reset`, `default_1h`, matching `terminal.WallSource` |
| Signatures | `Registry.get_provider_walls`; `get_account_walls`; `record_provider_wall`; `record_account_wall` |
| Wall rules | A stored wall row, of any cause, ends only at its deadline; nothing lifts it early. `record_account_wall` keeps ONE row per account and merges atomically: the later deadline wins, and a live credential or default cause outranks `vendor_reset` (a live `credential_rejected` keeps its label in either order). `get_account_walls` is `get_enforced_account_wall_rows`: per account, the latest of its live row and the latest future reset of its stored windows at utilization >= 1, however stale the reading. A reset at or before now walls nothing |
| Refuses | Unknown generation, invalid/bare credential account value, invalid wall source/time; the enclosing transaction rolls back |
| Consumers | L2 reads unexpired wall maps; L5 supplies wall records; L7 persists lifecycle and route observations |
| Columns | Every declared column must retain a row/registry writer. |
| Operation admission record | `admit_run(operation_admission=...)` validates and appends one safe checked lifecycle witness in the existing admission transaction, with no new table, column or generation. `operation_admission_read` verifies the chain and unique exact record; historical absence remains absence, while malformed, duplicated or unreadable evidence raises `RegistryError`. Private request paths, task prose, credentials and resolved host inventory are not recorded. |
| Effort record | `admit_run(effort_profile={requested, sent})` checks the record before any write and appends it as the run's `lifecycle` event `{"effort_profile": {...}}` inside the admission's own transaction: no new table, column, event kind or schema generation. Each value is null or non-empty text; any other key (an `executed` above all) is refused. `Registry.effort_profile(run_id)` reads only the journal, never the roster: no record answers every value `unknown`, and a broken chain, a malformed record, one on another event kind, or a second record is refused (`RegistryError`), never picked from or repaired. A run admitted before the record existed stays unknown; nothing is backfilled. An admission whose own transaction failed leaves no record. |
| Writer RED record | `admit_run(writer_red=WriterRedReceipt(...))` permits recorded native-writer profiles only for `implementation` and `verification`. Implementation requires one immutable, closed-shape receipt. An admission with a receipt refuses to start inside an open write. With a claim, one read refuses a held worktree with `WorktreeHeld` before Git, and keeps the claim generation of the worktree. Then, with no transaction open, admission uses the lower shared `red_witness` reader to read clone HEAD, so a slow Git call never blocks another writer. The admission is one write. Before its claim, the write compares the kept generation with the current one. A difference raises `WorktreeOwnershipChanged`, with a fixed text and `{"retryable": true}`, because another run could have held the worktree and moved HEAD during Git. There is no retry inside nSPAWN. After the claim, the write compares the HEAD with the receipt. Drift or bounded Git observation failure raises `WriterRedRefused`. Each refusal rolls back the run, receipt, claim and key in that same write: no early claim and no cleanup write exist. The `writer_red` lifecycle payload commits with the run, claim and key; rollback removes all of them. `writer_red(run_id)` returns receipt plus admission-event time, absent evidence as missing, and a broken event chain or duplicate, malformed or inconsistent evidence as `WriterRedCorrupt`. Persistence failures remain errors. No column, event kind or generation changes; no backfill. `SessionProfile` retains its seven-field shape. |

Project notices use the existing `notices` outbox, without an executor run.
`Registry.queue_project_notice` stores one bounded body per project and flag state.
`Registry.upgrade` adds the nullable `body` column without changing the schema generation.
The existing SessionStart drain returns these bodies once, in its delivery transaction.
Run notices keep their current renderer when `body` is null.

## L1q — the quota reading

| Contract field | Locked value |
| --- | --- |
| Owns | `nspawn/quota_sources.py` |
| Consumes | Native Codex app-server rate-limit snapshots (`account/rateLimits/read` responses and notifications) |
| Produces | `SourceReading(windows, fetched_at, source, absence, stale)` — one shape whatever the vendor speaks |
| Invariant | `windows` is empty **if and only if** `absence` names a reason; the constructor refuses both other quadrants. A source that failed is NEVER an account at zero. `stale` is a typed field, never a spelling inside `source` |
| Refresh | `nspawn_quota_show` with `refresh > 0` pulls native Codex account metadata without a model turn; every other account answers from what its runs' wire recorded. A provider with `quota_source = "colab"` is never pulled by `quota()`, whatever `refresh` is: `quota()` reads the `compute_balance` row and answers at once with `compute` (balance, rate per hour, active assignments, `fetched_at`), its age in `compute_updated` and `compute_stale` past 600 s, or `compute_absence`. The last failed pull rides in `compute_failure` and `compute_failed_at`. `nspawn quota record`, which the `nspawn-quota-record` user timer runs every 60 s under `flock -n`, runs `colab usage` once (stdin closed, only HOME and PATH, 5 s timeout) and is the only writer of that row. It refuses a reading older than the stored one, and a failure never erases the last good reading. A refresh updates USAGE only, through `record_account_usage`, the one writer a run's completion also uses: each observed bucket replaces its stored row unless that row was observed later, and an unobserved bucket is kept. A same-second tie keeps the higher utilization. It reads past a `vendor_reset` wall, never past a credential or default wall, and the reported `cooling_until` is the wall the picker enforces |
| Refuses | The Codex parsers NEVER raise: an unparseable snapshot is an absence naming its own reason. The Colab reader raises `QuotaSourceError`, and `nspawn quota record` stores it as the last failure. No number is reported that was not read |
| Consumers | L7 persists observations into L1 and answers the quota verb |

## LJ — the session journal

| Contract field | Locked value |
| --- | --- |
| Owns | `nspawn/journal/` (the row types, `FORMAT = 1`, the `Translator` protocol and `TRANSLATORS`; `claude.py`, `serve.py`, `show.py`, `activity.py`), the `journal_*` tables and indexes in `nspawn/schema.py` (`JOURNAL_DDL`, with `journal_run_thread` and `journal_run_updated` on `runs` for its lookups), the row shape `nspawn/schema/session-journal.v1.schema.json`, `~/.nott/sessions/media/`, and the `nspawn-session-serve` user unit (`ops/systemd/user/`). It is the only parse layer for vendor session records (CLAUDE.md, "Code boundaries") |
| Consumes | Claude Code session files (main sessions, Agent-tool subagents under `subagents/` and Workflow agents under `subagents/workflows/wf_<id>/`, with the `journal.jsonl` of each workflow for the end of its agents, and the parent's Workflow calls, launch results and task notifications and one listing of the run folder for the end of each workflow) in the default home, each roster account home of a Claude-client route, recorded cage homes and node homes, their pid records (`threads.claude_live`), and the roster's Claude token files. Codex has no translator: its sessions stay on the app-server reader. The registry owns store access (`open_store`) and effort validation (`effort_read`). The writer imports those ports, `owner_roster`, `threads`, `vendor_home` and `redact`, never `supervisor`, `mcp` or run lifecycle methods (`tests/test_journal.py`) |
| Produces | One store session per source file, with its source path and native vendor id. A copy in another home has a stable home-qualified journal id. Discovery metadata retains entrypoint, title, summary, modification time, node owner, account, parent evidence and distinct requested and sent effort. Native Claude links, including links of dropped records and logical compaction parents, commit in `journal_link`. Rows in seq order (`session`, `message`, `reasoning`, `tool_call`, `tool_result`, `child`, `hook`, `config`, `compaction`, `status`), one `journal_usage` row per model call (its last usage in source order) and one image file per distinct image. `nspawn session list [<vendor>] [--id <id>]... [--since <ISO>] [--count]` and `nspawn session show <vendor> <id>` print them as JSON lines with the token totals. `--id <id>` needs `<vendor>` and keeps the session `<id>` and each session whose id starts with `<id>.`, by the primary key of `journal_session`. `--count` ends the list with `{"count":N}`, where N is the number of session lines before it. The reader adds `run`, the run id, only to a top-level session whose resolved source home is `~/.nott/state/nspawn/runs/<run>/<vendor>`. It adds this field to the list entry and shown rows. Subagents and teammates under `subagents/`, other homes and homes that cannot resolve have no `run` field. Home resolution matches the writer. This uses the stored home and source path, not a run-list read, and does not change stored rows or the token totals. CLI list entries also carry `source_home`, the `source.home` of the session's one `session` row, and `source_home_refusal`. A session with no `session` row or with more than one gets the refusal `session row is not unique`. A row whose `vendor` or `id` is not the session's gets the refusal `session identity does not match`. With a refusal, `source_home` is null. The partial index `journal_session_row` finds the `session` rows, so the list reads no other row. The format check of that row reads it. Only the show footer carries `native_activity`. A list entry has none, and the list reads no `journal_source` activity row and no native file. The footer gives stored import facts (`mtime_ns`, consumed byte `size`, latest native `last_at`, all-time `max_gap_seconds`, and at most 256 recent `gaps` with timestamp `start`, `end` and `seconds`), or a safe `reason` when refused. The writer computes these facts in the same incremental pass as rows and commits them with the consumed cursor. Gap pairs follow native source order, including snapshot clocks in `snapshot.timestamp`; untimed records inherit no timestamp. Backward clocks create no negative gap, and a trailing partial line is not yet a record. The source row retains file identity and the previous clock across restarts. One export gate requires healthy source and session statuses, matching device, inode, byte size and nanosecond mtime, and stored size equal to the consumed cursor. It uses one source stat and reads no source bytes. Current fences require an owner-held readable regular file, one link, and owner-controlled directories without symlinks or group/other write permission. A failed, changed or incomplete source exports no activity facts. Rebuilds use retained device and inode only; a legacy source without identity keeps activity unknown. A modification without explained growth invalidates stored activity. Only a full rebuild from offset zero restores it. A change between rebuild batches keeps activity unknown. Operating-system read errors defer the source until the next cycle without failing translation; activity stays unknown until a clean import. An owner-path trust-fence refusal fails the source, persists its status, logs the refusal and untracks it. Repair does not readmit it. Malformed records and invalid clocks make only activity unknown; translation still counts malformed records and continues. CLI reads never open a vendor file. The `sessions` read of the CLI list and of the node host carries no native activity |
| Writer | `nspawn session serve` is the only writer. It polls by `os.stat`: each tracked source every 0.5 s, every home every 5 s. Startup queues existing files and resumes committed offsets. Live writes precede historical files, which run newest first. A background slot processes one existing batch before the next live poll. A growing source joins the live queue. Cold scans put older unchanged files in the background queue. Each session reports `importing` until its initial bytes and metadata are processed, then `done`. Metadata backfill keeps row and usage counts. A status row never moves the session's activity time, which comes from vendor rows. Each batch of at most 1000 whole lines commits its rows, usage, offset and translator state in one transaction; the offset moves by compare-and-set, so a second writer or a replay adds nothing. One cycle reads at most 8 MiB of a source, and the sources take turns. A status row and a session's metadata are written only on a change, a status row only when the source is caught up. A source's recorded facts and metadata are read once, then again only after a change: its size, modification time or metadata pass, a run whose `updated_at` moved, a child row that names it, or its parent's first commit. A cold cycle over unchanged sources runs no query per source, every lookup searches an index, and a start reads stored statuses and metadata without a write. A subagent is `live` while its parent's process holds it and its turn is open, else `ended`. A `finished: true` sidecar ends an Agent-tool subagent until the writer proves a later turn line by its own reads. A turn line is a user line, a queued command or an agent record that came after the sidecar. The proof has three parts. The writer read the sidecar. The line starts at or after the size of the next `lstat`. The sidecar did not change after that read. A cycle that cannot read the transcript has no proof, and the subagent is `ended`. Teammates and Workflow agents keep the `finished` rule. `linked` moves only over rows whose links are written. At start, a source whose `linked` is behind `consumed` (a release without links wrote past it, or the metadata pass was part-done) goes back through the metadata pass up to `consumed`. A session with no row has no status row and gets its metadata with its first row. A source that is gone ends its metadata pass with its stored rows and keeps its recorded modification time. A refused effort record leaves that effort unknown and is logged. The state of a Claude main session keeps its tracked Workflow runs from the ordinary import. The launch result of a new run adds a tracked run, which keeps its open launches. A Workflow call that waits for its result stays in the state until its result. When each launch of a run has an end, the status sweep closes the run in three steps. A valid parent read holds the end. Then one complete listing of the run folder follows, and then a valid parent read of a later cycle. A valid read has no unread byte, no partial record, no waiting Workflow call, no deferral, metadata version 1 and a retained identity. A failed listing stops the sequence and keeps the run, and the next valid read lists the folder again. Each listed agent with no end line gets a terminal certificate with its agent, run and call. The certificate also holds the device, inode and size of the agent file, and the number of `started` lines of the agent in the Workflow journal. Growth, a smaller size, another device or another inode voids the certificate, and so does a new `started` line of the agent. That line voids it also when the agent has its own end line. One function decides whether a certificate is void. Each reader calls it before it uses the certificate. The readers are the member check, the reconciliation and the retirement of a closed run, and the status. It compares the file and the count of `started` lines in the Workflow journal that the sweep read. It deletes a void certificate in one transaction before the reader acts, also while the journal tracks the run. A change of the modification time alone keeps it. The producer model bounds this rule: Claude Code only appends to an agent file and gives each launch new agent ids. A rewrite in place with the same length, by another writer, keeps the certificate. One transaction writes the certificates and the parent's entry, by compare-and-set on each offset and state. The entry of a closed run keeps all its members, and each sweep checks each member again. The run leaves the state only when each member holds a valid certificate, its own end line or a refusal. So the state keeps unresolved work only. The status of a member changes at the sweep of the third step. An invalidation of the parent drops its runs, and the metadata pass keeps none. This rule reads no parent byte and adds no scan. Its only reads are the listing and the bounded Workflow journal reader. A read takes each unchanged byte once while the held suffixes fit their bound of 2 × `read_bytes` (16 MiB). Each read cursor, the import and the metadata pass, holds the unread suffix of its last window. The writer serves those bytes only to that cursor at their offset, and only while the file keeps the device, inode, size, modification time and change time of the read that took them. Above the bound, the oldest suffix goes first, and the writer can read again only the bytes that the bound deleted. The held suffixes never use more memory than the bound. The writer does not read an unchanged unfinished record again: a growth, a rewrite or a new committed offset reads it again. Each poll decodes the activity of a source once for each change of it. A start sends a source without retained identity through the metadata pass only for its links or its metadata: a stored version 0, or `linked` behind `consumed`. Once a minute it logs the files statted, bytes read, rows written, unknown line types, the cycle p95 and maximum, the longest transaction and the bytes deleted by the bound. `bytes read` counts each byte that a read of a source returns. `bytes deleted by the bound` counts each held byte that the bound deletes |
| Store | The registry file `<dir>/nspawn.sqlite3`. `Registry.upgrade` adds the journal tables with `CREATE TABLE IF NOT EXISTS` at every open and keeps the schema version, so an older release opens the file and ignores them. Readers open it read-only. Additive columns keep the schema generation. `JOURNAL_SOURCE_COLUMNS` adds nullable JSON `activity` through `Registry.upgrade`. The existing bounded metadata pass rebuilds activity only with retained identity, without replaying rows or usage. It splits records on LF only, as the import does, and it reads no spill file |
| Refuses | A media root that is not this user's alone (exit 2 with its path); a second daemon on one `~/.nott` (a lock file); a source that shrinks (one `status failed`, reason `source shrank`, then untracked); a second source in the same home for a session another source feeds (its `journal_source` row records `failed`, `source mismatch`, and it adds no row); a write below 1 GiB free on `~/.nott` (`status failed`, reason `disk`); a secret set past its byte ceiling (`status failed`, reason `secrets`); a Workflow journal that the reader refuses (it sets no status, and the refusal below is the reason of its agent's status row). A failed listing of a Workflow run folder sets no status either. Its error code is the reason of the status rows of the run's agents. A line type outside the table is counted by name, never a failure. The Workflow journal reader refuses a journal that is not an owner-held readable regular file with one link (reason `workflow journal is not an owner regular file`). It refuses a journal larger than 64 MiB (reason `workflow journal exceeds byte ceiling`). It refuses a journal that it cannot open or read (reason `workflow journal unavailable`). It refuses a journal whose read ends before the size of its `fstat` snapshot (reason `workflow journal shorter than its snapshot`). In three cases the other rules give the status of the agent, as for an Agent-tool subagent. These cases are a missing journal, a complete read with no end line for the agent and a refused journal. A refusal is not terminal evidence: it gives no `ended` or `failed` status. A terminal certificate gives no status while the reader refuses the journal. The certificate stays, and the next read keeps it or voids it. The refusal is the reason of the status row that the other rules give on that pass. When those rules write no row on that pass, the refusal writes no row. `nspawn session show` prints the reason. The list rows of `show.sessions` and `show.facts` do not carry it. The reader reads at most the size of its `fstat` snapshot. After a short read, it reads on from the new offset until it reaches that size. Only a complete read goes into the cache. A refusal removes the cache entry of the journal, so the next pass reads the journal again. A line feed alone ends a journal record. The bytes after the last line feed are not yet a record. The reader skips a record that holds a carriage return |
| Secrets | Each text field goes through `SecretNeedles.redact_value` before it is stored. A token file that changes adds its secrets and keeps the old ones. Injected reminder and hook bodies keep only their kind and size; a hook's text is kept only when it blocks or fails. A spill file is read only by its base name inside the session's own `tool-results/` |
| Readers | `nspawn/journal/show.py` is the only reader of the format. `nott session list|show` runs `nspawn session list|show`, and the node host imports `nspawn.journal.show` in-process. Both call the same functions: `open_readonly()` (a read-only connection, or None when the file does not exist), `sessions(conn, statuses, vendor_id=None)` (the list row and `title`, the first owner text cut to 200 characters; `vendor_id` keeps one vendor session's copies), `bounds(conn, vendor, id)` (the oldest retained seq and head seq, or None when no rows exist), `replay_start(conn, vendor, id, limit, through_seq=H)` (the last omitted seq, or None when all retained rows through H fit), `rows_after(conn, vendor, id, seq, limit, through_seq=H)` (rows above seq through H, in ascending order), `rows_before(conn, vendor, id, seq, limit)` (the nearest rows below seq, in ascending order, with an integer limit from 1 through 200), `active_rows(conn, vendor, id)` (the active conversation, below), `data_version(conn)` and `media(file)`. The optional `through_seq` argument keeps a replay within its captured head. Without it, the existing read behavior is unchanged. The host uses these bounds and cursors to cap each load at 2000 rows. Backward pages do not change a live cursor. Each read of `journal_row` searches its key (vendor, session, seq). A store without the journal tables gives no rows and no error. A session whose `session` row names a format other than `FORMAT` raises `JournalFormatRefused`. `media` opens only a `<sha256>.<ext>` name in `~/.nott/sessions/media/`, with no symlink followed, and gives None for any other name, a symlink, a non-regular file or a missing file |
| Consumers | `nott session list|show` and the node host, through the readers above only. No other module reads the tables, the media files or a vendor file |

## L2 — ranking and four-step picker

| Contract field | Locked value |
| --- | --- |
| Owns | `nspawn/ranks.py` and `nspawn/picker.py` |
| Consumes | `Roster`, Claude `Provider` rows, caller provider/model/effort/class, producer name, current epoch seconds, and unexpired provider/account wall maps from L1 |
| Produces | `PickerResult(requested_provider, executed_provider, executed_account, model, effort, warning)` or `AllProvidersWalled(nearest_reset)` |
| Ranking | Judgment/planning/review/implementation use descending `Provider.strength`; mechanical fan-out uses descending `thrift`; design uses descending `design`; verification excludes the producer then uses descending `strength`; deterministic ordering is stable by provider name; the fail-closed `unclassified` ranks by descending `thrift` |
| Four steps | (1) validate an explicit model — and the provider's `model_fast` — against the selected provider's declared models (the CLI's `[1m]` suffix is ignored there); (2) otherwise use provider model, then roster default model; (3) with no explicit provider and a class, rank eligible unwalled providers; (4) with neither, use the declared default provider and roster default, falling through only to eligible ranked providers when the chosen route is walled. Steps 3 and 4 and `serviceable_routes` never choose a `named_only` provider: only a caller that names it, or one of its accounts, gets it |
| Account rule | Select only a roster alias that is not walled. The result carries the alias, not a token path or token bytes. Provider and account walls are independent. A `fill_first` provider takes the first declared account below its capacity, and the score decides only when every account is full. An account with `auth_env = "ANTHROPIC_API_KEY"` and no base url sends an Anthropic API key. It runs every model that its provider serves for an nSPAWN run (owner order, 2026-10-27). A canvas node never takes it: `route show`, the move and `route wall` exclude it, and `route start` refuses a node whose route names it. A canvas node stays on OAuth. |
| Signatures | `rank_providers(...) -> list[Provider]`; `pick_execution(...) -> PickerResult` |
| Refuses | Unknown provider/model/effort, no declared model, no eligible Claude provider/account, or all eligible routes walled; the last case reports the nearest future reset when one exists |
| Consumers | L7 admission and status persistence; L3 environment/argv construction |

Native API accounts (including Fugu) use the same `provider.secrets` directory
and `Provider.resolve_token_file(selected_alias)` as Claude. The selected
`<alias>.token` is read through the native owner/permission/size/symlink fence;
only its contents are injected under that account's `auth_env` name. That name
is the Codex profile's input contract, not an ambient credential source.
Missing or unsafe selected files refuse, with no ambient or other-account
fallback. The alternate `defaults.credential_env_file` loader is retired.
OAuth accounts continue to use their CLI's existing authenticated home.

## L3 — detached child custody

| Contract field | Locked value |
| --- | --- |
| Owns | `nspawn/child.py` |
| Consumes | L2's selected provider/account/model/effort, L8's binary and MCP plugin directory, caller prompt/cwd/session, one private run directory, and `SecretNeedles` |
| Produces | A `SpawnedChild` containing `subprocess.Popen[bytes]`, captured `ProcessIdentity`, separate stdout/stderr `OutputPump`s, and run directory |
| Spawn boundary | `subprocess.Popen(..., start_new_session=True)` with an argv sequence and closed environment; no shell |
| Termination | `SpawnedChild.stop_then_kill(expected)` revalidates the exact identity, sends `SIGSTOP` to its process group, then `SIGKILL`; no bare-PID fallback is admitted. The pair (and the reap after an observed exit) runs on its own thread under a reap fence: an interrupt never splits `SIGSTOP` from `SIGKILL`, and the leader is never reaped while a signal is owed. Once the signaler has started, the caller waits for it at most `SIGNALER_BOUND_SECONDS`, the reap included; a start that raises waits at most `SIGNALER_START_SECONDS` for the thread to enter; past either, `ChildIdentityError`, the kill not guaranteed sent. A reap that finds the leader already reaped by an earlier attempt's signaler under the fence returns that exit code; one whose exit observation meets ECHILD waits only while a reaper holds Popen's wait lock (at most `SIGNALER_BOUND_SECONDS`), then returns the code it stored or refuses at once. Interrupts are re-raised on a best-effort basis: Python cannot mask every bytecode, so one may escape unrecorded |

## L6 — the MCP replacement surface

Tool results up to 65,536 compact JSON bytes remain inline. Larger results return
JSON containing `preview` (the first 65,536 serialized bytes), `path` (an absolute
path to the complete JSON file, mode `0600`), and `bytes` (the full byte count).
Run-specific answers spill into that run's existing directory; fleet/roster
answers use a fresh private directory under the configured run root (default
`~/.nott/state/nspawn/runs`). Repeated reads create distinct files. A missing run
directory or failed write returns a typed error and publishes no artifact path.
Artifact creation and cleanup use a no-follow directory descriptor, so replacing
the run directory with a symlink cannot redirect the write. Before publishing a
path, the door checks directory/file identity and resolved containment; a changed
directory or artifact causes a typed refusal and preserves the session.
JSON serialization escapes non-ASCII text, so the preview boundary preserves
bytes without splitting a UTF-8 character; the preview need not itself be valid JSON.

`McpServer.handle` rejects tools/call params above 1,048,576 compact JSON bytes
(`MAX_MCP_PARAMS_BYTES`) with `-32602` naming the ceiling and observed size and
preserving the request ID, before invoking a tool. The stdio reader has a
separate 2,097,152-byte (2 MiB) memory bound (`MAX_MCP_FRAME_BYTES`) for its
trusted spawner. Frames above the params ceiling but within that reader bound
receive the typed refusal and the same session can answer its next request.
Above the reader bound, the session closes before parsing;
the reader is not drained or reused afterwards.

## Review head admission

L1 owns the additive `review_heads` table at schema version 7. Each row names
one subject, spec revision, candidate and creation time. New rows write epoch
1. No run owns these rows. A transaction checks and records each new head
before L7 calls witness admission. A later route failure does not remove a
counted head.

L6 `nspawn_review_start` takes optional `subject` and `candidate` together.
Its prompt must contain the whole candidate. A present `.nott-review-sha`
regular file must match it. `ReviewCandidateInvalid` refuses invalid fields
and extends `InvalidRunRequest`. A call without the fields keeps its old
behavior and key. The CLI `nspawn review admit --stdin` counts the same ledger
from one candidate line and at most one spec revision line, without checking
the caller's marker.

L7 counts each distinct head of a subject once. Review rounds have no limit, so
the count is a measure and never refuses a head. Lower-case hex values identify
both heads and revisions. The answer keeps `budget` at 1 for the hook readback.
